Workflow

Message 0 is never hidden, whatever this is set to. The pinned tail keeps the chat from going blank the moment a summary is generated, and leaves the model some verbatim recent context.

Where summarization runs

tokens — 0 uses the main API's

Summarising is a different job from roleplaying and often wants a different model. Picking a profile here sends only Recall's requests through it — your selected profile is untouched. A profile stores one model, and ST can only list models for the source it is currently connected to, so the model field is free text and a typo surfaces as the provider's own error.

The profile's own generation preset comes with it: temperature, top P and the rest of its samplers are what the summary is generated under. Edit that preset in ST to change them. On the main API nothing is substituted — the request goes out the same way your chat's would.

Reference material

Sent alongside the chat so the summariser knows who the participants are rather than inferring it. Marked as background, not as events to summarise. These come out of the same token budget as the chat history, so each one enabled means less history fits in a single pass.

From your chat's preset

Your main prompt, post-history instructions and any custom prompts, read from the preset your chat is running on — not from the profile above. They tell the summariser the register the chat is written in and what it is allowed to be explicit about, which nothing else here does. Sent quoted and disclaimed, as instructions belonging to the chat rather than to the summary, so the summariser does not start writing the next reply instead. Your summary block is safe to tick: the macro inside it is removed first, so it contributes its wrapper and never a second copy of the summary being revised.

Coming from the built-in Summarize

On a chat the built-in already summarised, {{recall}} resolves to that summary until you generate your first, and it seeds that first generation so Recall revises it instead of writing a new one from scratch. Read-only, and it does not need the built-in to be enabled — the text lives in the chat file. This is also what makes an old chat with already-hidden messages safe to summarise without unhiding everything first.

Context nudge

In tokens, measured against the last prompt actually sent. Leave at 0 to track 80% of the current context limit. Fires once per crossing, then stays quiet until a summary brings usage back down.
